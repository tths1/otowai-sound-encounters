# AI 音频生成接入设计

## 目标

将空耳制造器的“朗读生成句子”从浏览器本地 `Web Speech API` 扩展为可接入外部 AI 音频接口的播放链路，并保持当前的朗读时长匹配、保存音频、分享朗读和浏览器回退能力。

## 当前链路

- `static-site/app.js` 负责生成假名、测量中文与假名的基准时长、调用 `speechSynthesis` 播放。
- 生成结果区域提供速度滑条、日语声音选择、朗读、保存和分享按钮。
- 当前保存音频依赖 `getDisplayMedia` 捕获标签页音频，移动端兼容性有限。

## 设计决定

### 1. 音频提供器边界

网页侧只依赖一个统一提供器接口：

```js
generateAudio({ text, language, voice, speed })
  -> Promise<{ blob, mimeType, duration, provider }>
```

提供器返回可播放的 `Blob`、MIME 类型、音频时长和来源标识。网页不关心外部服务的字段名称、鉴权方式或具体响应结构。

### 2. 服务端代理

新增 `netlify/functions/audio.ts` 作为 AI 音频接口代理。浏览器只向 `/api/audio` 发送假名、语言、音色和可选速度；外部服务地址、密钥和模型配置只从 Netlify 环境变量读取。

在接口格式未知时，代理先提供配置校验、请求边界和统一错误结构；外部服务适配器保留为单独函数，等接口资料齐全后接入，不把猜测写进公开运行逻辑。

### 3. 播放与回退

- 已配置并成功生成 AI 音频：使用 `HTMLAudioElement` 播放，显示“AI 音频”。
- 接口未配置、网络失败、返回格式不支持或生成超时：显示可理解的提示，并自动回退到当前浏览器朗读。
- 回退不改变用户输入、假名结果、历史记录和时长测量。

### 4. 时长匹配

- 中文原句仍优先使用现有静音测量，测量失败时使用估算值。
- AI 音频返回后读取 `audio.duration`；播放时使用 `playbackRate = 音频时长 / 中文目标时长 × 用户微调值`。
- 若外部接口支持 `speed`，代理可把目标速度传给接口；若不支持，网页端仍能通过播放速率匹配听感。
- 下载按钮保存 AI 返回的原始音频 Blob；播放速率调整只影响播放，不伪装成重新编码后的文件。

### 5. 配置和隐私

新增 `.env.example` 中的 AI 音频配置说明，明确列出接口地址、密钥、模型、超时和启用开关。任何密钥不得进入 `static-site/`、`dist/` 或浏览器 localStorage。访客输入只在用户点击生成朗读后发送到已配置的音频代理。

### 6. 用户界面

在生成结果区增加来源状态和生成中状态：

- `AI 音频生成中…`
- `AI 音频已就绪`
- `AI 音频不可用，已切换浏览器朗读`

已有朗读、保存、分享和速度控件保留原位置；不要求访客理解接口、模型或环境变量。

## 错误处理

- 未配置：代理返回 `503` 和 `AUDIO_PROVIDER_NOT_CONFIGURED`。
- 鉴权失败：代理返回 `502`，前端转为回退提示，不暴露密钥或上游响应正文。
- 上游超时：代理在有限时间内终止请求，返回 `504`。
- 非音频响应或空响应：返回 `502`，前端回退。
- 用户取消播放或下载：清理对象 URL、音频元素和加载状态，不污染历史记录。

## 测试边界

- 提供器能把统一请求转换为代理请求，并能识别音频响应。
- 未配置、超时、非音频和上游错误均产生稳定的前端回退行为。
- AI 音频的播放速度根据实际 `duration` 计算，用户微调能叠加。
- 下载保存返回 Blob，浏览器朗读回退仍可用。
- 不把 API 密钥写入静态文件、localStorage、日志或错误提示。

## 待用户提供的接口资料

实现外部适配器前只需要以下资料：接口 URL、鉴权方式与请求头、请求 JSON 示例、返回音频格式（例如 MP3/WAV/OGG）、音色字段和速度字段名称。接口资料到位后，适配器不需要改变页面层接口。
