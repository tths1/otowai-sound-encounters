# 《音逢｜中日谐音文化小志》技术说明

## 1. 项目简介

“音逢”是一个中日谐音文化探索网页。项目以“声音联想”而非“语义翻译”为核心：用户输入一句中文后，系统按汉字拼音与日语假名的近似音节，逐字生成一段可朗读的假名表达。例如，用户可以把“忽逢桃花林”体验为“ふーふん たお はりん”。

项目希望把抽象的语音关系变成可输入、可搜索、可朗读、可校对的交互体验，帮助使用者以轻松的方式接近汉字文化圈中的声音变化。

在线地址：[https://otowai-sound-encounters.netlify.app/](https://otowai-sound-encounters.netlify.app/)

## 2. 解决的问题

常见的中日语言内容往往停留在静态知识介绍，用户难以直接体验“一个中文句子在日语音感中会怎样变化”。本项目将这一过程拆为三个可见步骤：

1. 输入原句；
2. 基于音感字库生成对应假名；
3. 用日语语音朗读，并让朗读时长接近中文原句。

同时，项目将管理规则和公开使用区分开：使用者可以自由体验，维护者可以在管理端继续校对音感映射。

## 3. 核心功能

### 3.1 空耳制造器

- 支持中文、日文和符号混合输入；
- 按字符拆分处理，避免出现语义翻译；
- 输出假名化结果和对应发音；
- 自动将未记录的同音字归入已有拼音规则，便于后续维护；
- 保存最近生成历史，方便反复试听。

### 3.2 音感映射与同音字复用

项目以“拼音—假名”作为主规则。相同拼音的常用汉字共用同一套假名；例如“他、她、它”同为 `ta`，可使用同一读音规则。遇到多音字时，可通过不同拼音行区分，如“行（xing）”与“行（hang）”。

生成优先级如下：

```text
手工校对的拼音规则
        ↓
已有同音字组
        ↓
自动生成的待校对音组
        ↓
音节簇回退策略
```

这种设计让人工校对结果始终优先于自动生成结果。

### 3.3 朗读时长自动匹配

若只按固定速度朗读假名，生成结果较长时会明显拖慢节奏。项目通过浏览器 Web Speech API 静音测量两段文本的基准朗读时长：

```text
中文原句基准时长 = T_cn
假名基准时长     = T_ja
自动朗读语速      = T_ja / T_cn
```

系统采用这个语速朗读假名，使其预计时长接近原句。第一次使用同一句时需要短暂测量；测量结果会缓存在当前会话中，之后再次试听可直接播放。用户还可用滑条在自动结果之上做微调。

### 3.4 词集与交互体验

- 首页展示每日谐音和声音相似度；
- 词集支持按中文、假名、出处搜索及类别筛选；
- 主题可切换为深色模式；
- 按钮具有轻微形变反馈，并为“减少动效”用户关闭过渡动画；
- 页面采用响应式网格，在手机端自动改为单列布局。

### 3.5 映射规则维护

公开页面默认不展示规则编辑区。管理端通过 Netlify Functions 读取和保存拼音规则；规则保存在 Netlify Blobs 中，写入请求需要管理员身份验证，从而避免公共访问者修改词库。

## 4. 技术架构

```text
浏览器
 ├─ 静态页面：HTML + CSS + 原生 JavaScript
 ├─ 音感转换：拼音数据 / 同音规则 / 回退策略
 ├─ 本地状态：localStorage（主题、历史、草稿）
 ├─ 朗读：Web Speech API
 └─ 管理请求：/api/mappings
                    ↓
            Netlify Functions
                    ↓
       Netlify Blobs（映射规则存储）
```

## 6. 创新点

1. **从“翻译”转向“音感”**：明确禁止意译，避免常见翻译工具将声音游戏变成语义转换。
2. **逐字与同音字组结合**：既让句子能完整生成，又保证同音汉字的输出一致。
3. **朗读节奏可校准**：不只输出文字，还将中文与假名的语音时长纳入交互设计。
4. **可持续校对的字库**：将自动补充和人工规则分层，后续可不断扩充、修正。
5. **公开体验与私有维护分离**：普通用户专注使用生成器，管理员维护词库质量。

## 7. AI 辅助开发方案

本作品采用“AI 辅助开发 + 可解释规则运行”的组合方式。AI 在开发阶段协助需求分析、页面设计、代码审查、测试样例设计与问题定位；公开网站运行时不调用付费大模型 API，也不上传用户输入。

### 7.1 技术过程

开发过程遵循“自然语言需求 → AI 协助拆解方案 → 人工校对音感规则 → 浏览器实测 → 迭代修正”的闭环。针对“不允许意译”“同音字要共用假名”“朗读时长接近原句”等要求，AI 提供候选实现，作者以实际页面输出和试听结果作最终判断。

### 7.2 集成方法

AI 不嵌入访客运行链路。运行时由原生 JavaScript 读取本地映射表、调用 Web Speech API，并通过 Netlify Functions/Blobs 完成管理员映射维护。这使输出可追溯、可修改，且不依赖模型服务可用性。

### 7.3 优化策略

- 人工校对规则优先于自动候选，避免自动建议覆盖已确认读音；
- 同音字按拼音复用，多音字单独建行；
- 用静音测时结果计算语速，降低假名长度造成的节奏偏差；
- 不保存或上传访客句子到第三方模型，兼顾成本、隐私和稳定性。

## 8. 测试与验证

已完成的主要验证包括：

- 中文、日文和混合输入的生成流程；
- 相同拼音汉字的复用与多音字区分；
- 输入、生成、复制、朗读、历史记录、深色模式等核心交互；
- 手机与桌面端布局；
- Web Speech API 的时长匹配显示。测试句“今天我们一起学习中文”实测中文约 2.5 秒，系统生成假名后预计同为约 2.5 秒。

## 9. 后续迭代

- 支持词条投稿审核与公开展示；
